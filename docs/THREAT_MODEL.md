# 第一阶段威胁模型

## 保护资产

- DeepSeek 上游 Key、LiteLLM Master Key；
- 员工虚拟 Key和一次性激活码；
- 员工身份、部门、额度与用量元数据；
- 本地代码、提示词、会话和模型回复；
- 更新签名私钥与发布清单。

## 主要威胁与控制

| 威胁 | 边界 | 第一阶段控制 | 后续验证 |
|---|---|---|---|
| 激活码数据库泄露 | Control Plane DB | HMAC-SHA-256 + 服务端 Pepper，只存哈希 | Pepper 进入密钥管理系统 |
| 激活码重放/并发兑换 | 激活 API | 短期预览会话、单次消费、接口限流 | PostgreSQL 行锁与事务集成测试 |
| 虚拟 Key 泄露 | Windows 客户端 | 仅子进程环境传递；不写日志 | 接入 Credential Manager、诊断包扫描 |
| 上游 Key 泄露 | 网关 | 只通过服务器环境密钥注入 | 密钥轮换演练 |
| 提示词/代码被记录 | Harness/网关 | Harness 遥测强制关闭；LiteLLM 关闭消息日志和异常正文 | 黑盒检查 stdout、DB、错误响应 |
| 本地 Harness 暴露到局域网 | Windows 客户端 | 固定 `127.0.0.1`，不允许 `0.0.0.0` | 端口扫描自动化测试 |
| 伪造更新包 | 更新 CDN/客户端 | RSA-PSS 清单签名、SHA-256 包校验 | 签名密钥隔离、篡改测试、回滚测试 |
| 员工绕过公司网关 | 员工设备 | 壳不提供个人 Provider；固定启动环境 | 需要终端/网络出口策略才是强边界 |
| 管理接口被普通 Key调用 | LiteLLM | Master Key 仅 Control Plane 可见；调用面与管理面分离 | 防火墙与反向代理策略 |
| 金额口径错误 | LiteLLM/报表 | 稳定模型别名、维护价格表 | 与上游账单月度核对 |

## 明确残余风险

拥有本机管理员权限的员工仍能修改本地文件或启动其他客户端。没有公司终端管理和出口控制时，“只能使用公司网关”是产品约束，不是不可绕过的安全边界。
