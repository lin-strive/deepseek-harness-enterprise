# 开源发布检查清单

## 为什么不能直接公开原仓库

Git 删除或后续替换只会改变新提交，不会移除旧提交、标签、Release、PR 引用和缓存中的历史对象。曾经提交过的公司名称、Logo、包名、服务器地址或运维记录仍可能被浏览和下载。

本项目首次公开应从经过审计的工作区快照创建一个新的、非 Fork 仓库。不要复制原仓库的 `.git`、标签、Release、PR 或 Actions 缓存。

## 快照准备

- [ ] 品牌扫描通过，不含真实公司名称、缩写、包名或旧 Logo；
- [ ] 不含真实 IP、SSH 目标、账号、备份路径、支持编号或部署时间线；
- [ ] 不含 `.env`、API Key、私钥、证书密码、数据库转储或生产日志；
- [ ] `.env.example` 只包含明确的占位值和保留示例域名；
- [ ] 构建产物、Runtime、`node_modules`、`target`、`bin`、`obj` 和安装包未纳入版本库；
- [ ] README、架构、部署和安全文档使用通用模板；
- [ ] 所有自动化测试和发布扫描通过；
- [ ] 已完成第三方依赖许可证与商标使用审查；
- [ ] 已选择并加入项目许可证；
- [ ] 已配置私密漏洞报告渠道。

## 创建全新公开仓库

1. 将干净工作区复制到一个不含 `.git` 的新目录；
2. 运行 `git init -b main`；
3. 使用 GitHub noreply 邮箱配置提交作者；
4. 再次运行 `verify-public-release.ps1`；
5. 确认 `git rev-list --all --count` 在首次提交前为 `0`；
6. 创建单一根提交；
7. 在 GitHub 新建非 Fork 仓库，不导入旧仓库；
8. 推送 `main`，不要推送旧标签或其他 refs；
9. 从未登录浏览器检查代码、提交作者、文件历史和仓库可见性。

## 发布后

- [ ] 启用 Secret Scanning、Push Protection、Dependabot 和分支保护；
- [ ] 检查仓库成员、Actions 权限和 Release 上传权限；
- [ ] 安装包使用独立的 Authenticode 证书签名，证书私钥不进入 GitHub；
- [ ] 若发现泄密，先轮换凭据，再处理历史和缓存，不仅是删除文件。
